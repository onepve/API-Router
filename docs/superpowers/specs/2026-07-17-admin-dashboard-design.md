# API Router 管理页面重构设计

日期：2026-07-17

## 目标

将现有管理页面重构为桌面优先的实时运维控制台。首页必须同时呈现路由健康、请求趋势、Token 与成本、Key 可用性、端点可用性和最近请求流；模型、端点、Token、配置继续作为二级工作区，操作应更紧凑、高效且一致。

本次不改变现有路由配置语义，不引入前端构建工具，也不持久化请求日志。

## 目标用户与核心任务

目标用户是 API Router 的维护者，主要任务按优先级排序：

1. 快速判断服务、端点和 Key 是否健康。
2. 观察最近请求、异常状态、模型分布和延迟。
3. 查看 Token 消耗与预估成本。
4. 定位异常模型或端点，并直接跳转处理。
5. 管理模型、端点、Key 和配置文件。

## 视觉方向

采用“运维指挥台”布局，强调高信息密度和稳定扫描，不使用营销式大标题或装饰性卡片堆叠。

### 色彩

- 工作区背景：`#F3F5F7`
- 面板背景：`#FFFFFF`
- 深石墨导航：`#202830`
- 主交互青绿：`#167C73`
- 正常绿色：`#2F8F62`
- 警告琥珀：`#C27A21`
- 错误红色：`#C84A42`
- 主文本：`#17212B`
- 次级文本：`#61707D`

状态颜色只编码真实状态，不用作大面积装饰。界面避免单一青色调，图表使用青绿、蓝、琥珀和红色的有限组合。

### 字体与图标

- 界面正文：系统无衬线字体栈。
- 数值与日志字段：`SFMono-Regular`、Consolas、等宽字体栈。
- 图标：Lucide。emoji 不再承担导航或按钮图标功能。

### 形态

- 面板圆角不超过 8px。
- 页面分区使用网格和分隔线，不使用卡片嵌套。
- 工具栏、筛选器和表格行保持稳定高度。
- 动效仅用于抽屉、状态更新和日志新行，支持 `prefers-reduced-motion`。

## 信息架构

左侧导航保留五个工作区：

1. 仪表盘
2. 模型
3. 端点
4. Token 与成本
5. 配置

侧栏桌面宽度约 208px，可折叠为图标栏；平板自动收窄；手机使用抽屉导航。顶部工具栏显示服务状态、数据更新时间、自动刷新状态和手动刷新操作。

## 首页仪表盘

### 第一行：核心指标

固定展示以下指标：

- 今日请求数
- 今日 Token
- 今日预估成本
- 请求成功率
- P95 延迟
- 有效 Key / Key 总数
- 可用端点 / 端点总数
- 异常请求数

Key 指标同时展示冷却数量；端点指标同时展示不可用数量。指标可点击，并联动过滤下方健康矩阵或请求流。

### 主工作区

桌面使用约 65% / 35% 两栏布局。

左侧包含：

- 请求量与错误率组合趋势
- Token 与成本组合趋势
- 模型请求或 Token 分布
- 端点健康矩阵

右侧常驻“最近请求流”。每行展示：

- 时间
- HTTP 状态
- 模型
- 接口路径
- 耗时
- Token

选择日志行后展开：

- 原始模型与实际转发模型
- 上游端点
- 是否流式
- 重试次数
- 错误摘要

日志区支持暂停界面更新、文本搜索，以及按模型、状态和接口过滤。暂停不会停止后端记录。

### 底部与跳转

端点健康矩阵按模型或端点池分组，展示有效 Key、总 Key、冷却 Key、健康比例和最近异常。异常日志与健康矩阵可跳转至对应模型或端点详情。

## 请求日志后端

### 数据结构

新增内存 `RequestLogStore`，使用固定容量环形缓冲区，默认保留最近 500 条。服务重启后日志清空。

每条记录包含：

- `id`：单调递增游标
- `timestamp`
- `originalModel`
- `resolvedModel`
- `path`
- `status`
- `durationMs`
- `totalTokens`
- `upstreamBaseUrl`
- `stream`
- `retryCount`
- `error`

不得记录请求正文、响应正文、API Key、鉴权头或带敏感查询参数的完整 URL。

### 记录时机

- 非流式请求：收到最终上游响应或确定转发失败后记录。
- 流式请求：流完整结束或中断后记录最终状态。
- 重定向：保留用户请求的原始模型，并记录最终解析模型。
- 多 Key 重试：只记录一次最终请求结果，同时记录尝试次数。

### API

新增受现有管理鉴权保护的接口：

`GET /admin/request-logs`

支持参数：

- `after`：只返回大于该 ID 的记录
- `limit`：默认 100，最大 500
- `model`
- `status`
- `path`

返回记录列表和最新游标。

新增仪表盘聚合接口：

`GET /admin/dashboard-summary?window=24h`

返回：请求数、成功率、P95、异常数、有效 Key/总数、冷却 Key、可用端点/总数，以及趋势所需的时间桶数据。Token 和成本继续复用现有 TokenStore 与 ModelCatalog 计算逻辑，避免重复存储。

### 前端更新策略

- 请求日志每 2 秒使用 `after` 游标增量轮询。
- 汇总、健康和趋势数据沿用自动刷新周期，并支持手动刷新。
- 请求日志接口失败时保留旧数据并标记“数据已过期”。
- 游标失效或服务重启后，前端自动获取最新快照。

## 二级工作区

### 模型

- 左侧可搜索模型列表，显示端点数量、Key 健康和支持的接口类型。
- 右侧为模型详情、共享端点池、独占端点和 Key 状态。
- 新建与编辑使用右侧抽屉；删除使用确认对话框。
- 端点和 Key 操作完成后局部刷新，不重载整页。

### 端点

- 使用可排序表格展示 URL、所属模型或池、权重、可用 Key/总 Key、健康度和最近异常。
- 展开行查看 Key 状态。
- 支持模型、健康状态和端点池过滤。

### Token 与成本

保留并整理现有能力：

- Token 趋势
- 请求数趋势
- 模型占比
- 输入、输出与缓存 Token
- 模型定价
- 输入、输出、缓存和总成本明细

所有图表共享模型和时间范围筛选器。

### 配置

- CodeMirror 使用全高布局。
- 顶部提供重新加载、下载和保存。
- 显示未保存状态、保存中、保存成功或具体校验错误。
- 存在未保存内容时，离开页面需确认。

## 前端代码结构

不引入 bundler。将当前单文件拆分为：

- `src/admin/page.ts`：HTML 壳和资源引用
- `src/admin/styles.ts`：管理页 CSS 响应
- `src/admin/script.ts`：管理页交互脚本响应
- `src/admin/routes.ts`：页面资源、日志与管理 API 路由

后端继续由 Deno 提供资源。ECharts、CodeMirror 和 Lucide 保持浏览器端加载；资源加载失败时，核心表格与管理操作仍应可用，图表区域显示明确错误状态。

## 错误与空状态

- 接口失败时保留最近一次成功数据，不清空整个页面。
- 每个区域独立显示加载、空、过期或错误状态。
- 无请求日志时提示等待新请求，并保留过滤器。
- 无异常时显示正常状态，不使用大面积插画。
- 删除、保存等危险操作必须反馈成功或具体错误。

## 响应式与可访问性

- 1440px 与 1920px 桌面充分利用横向空间。
- 900px 以下将仪表盘主工作区改为单列，请求流置于趋势下方。
- 600px 以下使用抽屉导航，指标改为两列，表格可横向滚动。
- 所有图标按钮提供 `title` 或 tooltip。
- 键盘焦点可见；模态框和抽屉支持 Esc 关闭。
- 文本不使用视口宽度缩放，长模型名和 URL 使用省略与可复制详情。

## 测试与验收

### 后端测试

- 环形缓冲区容量与游标查询。
- 日志过滤和最大 limit。
- 非流式成功、重试后成功、最终失败。
- 流式成功与中断。
- 确认日志不包含 Key、鉴权头或请求正文。
- 仪表盘汇总中的成功率、P95、Key 和端点计数。

### 前端验收

- 仪表盘完整展示请求、Token、成本、延迟、Key、端点和异常指标。
- 日志轮询可增量更新、暂停、恢复和过滤。
- 模型、端点、Token、成本、配置原有能力均保留。
- 桌面、平板、手机无重叠、截断或不可操作控件。
- 使用 Playwright 截图检查 1440x900、1920x1080、768x1024 和 390x844。
- 验证 CDN 资源失败时仍可进行核心管理操作。

## 非目标

- 不持久化请求日志。
- 不记录请求或响应正文。
- 不增加用户系统、角色权限或多租户能力。
- 不增加 WebSocket 或 SSE。
- 不改变现有模型路由和负载均衡语义。
